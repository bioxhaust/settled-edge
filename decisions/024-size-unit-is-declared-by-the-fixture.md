# 024 — Единица размера объявляется фикстурой, а не выводится парсером

**Статус:** принято. **Владелец правки:** тимлид (`arb-types`, `arb-venue`, фикстуры).
**Основание:** `decisions/019`, `decisions/023` пункт 4, `OPEN.md` D5.

## Чем это вызвано

Предыдущая сессия оборвалась посреди шага 1 раунда 2. `ContractSpec` получил
обязательное поле `size_unit`, но ~25 мест конструирования не были обновлены, и
`cargo build --offline --workspace` падал. Это состояние закоммичено как
`4e50ee5`, чтобы точка возврата существовала: до этого коммита рабочее дерево не
было под версионным контролем вообще, и каждый обрыв связи стоил всю недоделанную
дельту.

## Решение

**1. `size_unit` — обязательный ключ фикстуры.** Парсер требует его через
`instrument.require("size_unit")` и отвергает файл без него с `MissingKey`.
Значения: `base` или `contracts`, ничего больше.

**2. Вывод единицы из `contract_size` запрещён.** `SizeUnit::implied_by`
существует и остаётся — но только для сверки объявленного с подразумеваемым, не
для заполнения поля. Причина в `decisions/019`: на Binance один контракт равен
одной монете, поэтому неверный вывод там численно невидим, а на Gate ошибается в
10 000 раз. Ошибка, невидимая на первой проверяемой площадке, — худший вид.

**3. Все 16 фикстур объявили единицу:** 15 линейных и спотовых — `base`, один
обратный (`okx-btc-usd-inverse-perp`) — `contracts`. Значения не измерены на
живом API; они переписаны из комментариев, которые уже были в тех же файлах, и
остаются `[предположение]` наравне со всем остальным в них.

## Что осталось незакрытым

Единица теперь **объявлена**, но всё ещё не **проверена**. Совпадение
объявленного с `implied_by` парсер не требует — по документации самого
`ContractSpec::validate` расхождение является сигналом о данных, а не поводом их
подровнять. Пока живой API недоступен, `size_unit = base` в фикстуре — это
утверждение о нашей памяти об API, а не о площадке. Пункт остаётся в
`FIXTURES-UNVERIFIED.md`.

`OPEN.md` D5 закрывается частично: формат теперь несёт единицу явно и парсер
отказывает файлу без неё — но сверка с `ContractSize` не обязательна, поэтому
взаимно противоречивая фикстура всё ещё принимается.

## Побочные правки, сделанные тем же ходом

- Тесты `arb-venue` считали номера строк в своих строковых константах жёстко
  зашитыми числами. Константы выросли на строку, числа исправлены (26→27, 49→51)
  вместе с прозой, которая их обосновывает. Класс хрупкости отмечен, но не
  устранён: тест, который считает строки руками, будет ломаться при каждой правке
  константы.
- Хелперы спеков в `arb-math`, `arb-scan`, `arb-adversary` получили единицу по
  конвенции 019. Все спеки в тестах `arb-scan` — линейные или спотовые, поэтому
  там `Base` везде и это проверено, а не предположено.

## Состояние после правки

`cargo build --offline --workspace` — чисто, ноль предупреждений.
`cargo test --offline --workspace` — 662 теста зелёные, ноль падений.
`cargo run -p arb-engine -- replay fixtures/` — 16 инструментов, 8 площадок,
46 пар, exit 0.
